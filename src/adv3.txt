#D 64|RH134|Networking: link aggregation (bonding)|Combine NICs into a bond for redundancy or throughput.
Q What is network bonding?
+ Combining two or more NICs into one logical interface for redundancy or bandwidth
- Splitting one NIC into many
- A firewall feature
- A DNS technique
E On RHEL 9/10 use bonding; the older "teaming" (teamd) was removed.
Q Which bond mode gives simple failover with one active NIC at a time?
+ active-backup (mode 1)
- balance-rr (mode 0)
- 802.3ad (mode 4)
- broadcast (mode 3)
E active-backup needs no special switch support; 802.3ad (LACP) needs a configured switch.
Q What does the miimon bond option do?
+ Sets how often (ms) to check link state for failover
- Sets the IP address
- Sets the MTU
- Sets the DNS server
E e.g. miimon=100 checks every 100 ms.
Q In a bond, the member interfaces are called:
+ Ports (formerly "slaves"), controlled by the bond (the "controller")
- Bridges
- VLANs
- Zones
E Each port is its own connection profile with the bond as its controller/master.
Q Which file shows a bond's live status and active port?
+ /proc/net/bonding/bond0
- /etc/bond0.conf
- /sys/bond0
- /var/log/bond0
E It lists the mode, each port's link state, and the currently active port.
Q Why use active-backup mode for a server with two switches?
+ It survives a switch or cable failure with no special switch config
- It doubles throughput automatically
- It encrypts traffic
- It is required for DNS
E Redundancy without LACP; throughput bonding (802.3ad) needs switch support.
C Create a bond interface bond0 in active-backup mode with miimon 100.
A nmcli con add type bond con-name bond0 ifname bond0 bond.options "mode=active-backup,miimon=100"
E Give it an IP with `ipv4.addresses`/`ipv4.method manual` as the task requires.
C Add the NIC eth1 as a port of bond0.
A nmcli con add type ethernet con-name bond0-port1 ifname eth1 master bond0
E Repeat for eth2 as bond0-port2; the ports have no IP of their own.
C Show the live status and active port of bond0.
A cat /proc/net/bonding/bond0
E Also `nmcli device status` shows the bond and its ports.
T Build a redundant bond (exam-plus)
S Create bond0 (active-backup, miimon=100) with a static IP, add two NICs as ports, bring it up, and verify failover status.
X nmcli con add type bond con-name bond0 ifname bond0 bond.options "mode=active-backup,miimon=100" ipv4.addresses 192.168.100.20/24 ipv4.method manual
X nmcli con add type ethernet con-name bond0-p1 ifname eth1 master bond0
X nmcli con add type ethernet con-name bond0-p2 ifname eth2 master bond0
X nmcli con up bond0
X cat /proc/net/bonding/bond0
V ip -br a shows bond0 with the IP; the bonding file lists two ports and one active
T Test bond failover
S Bring down the currently active port and confirm the bond fails over to the other, keeping connectivity.
X grep -i 'Currently Active' /proc/net/bonding/bond0
X nmcli con down bond0-p1
X cat /proc/net/bonding/bond0      # active port switched to p2
X ping -c3 192.168.100.1
V connectivity survives; the active port changed
T Persist and reboot-test the bond
S Ensure the bond and both ports autoconnect and survive a reboot.
X nmcli -f connection.autoconnect con show bond0
X nmcli con mod bond0 connection.autoconnect yes
X reboot
V after reboot: ip -br a shows bond0 up with two ports
T Inspect bond configuration
S Show the bond's options and each port's controller relationship.
X nmcli -f bond.options con show bond0
X nmcli -f connection.master,connection.slave-type con show bond0-p1
V you can read the mode/miimon and confirm the ports belong to bond0

#D 65|RH134|Networking: advanced firewalld|Use zones, rich rules, masquerading and port forwarding.
Q A firewalld "zone" represents:
+ A trust level with its own rules, bound to interfaces or source addresses
- A DNS domain
- A subnet mask
- A VLAN
E Common zones: public, trusted, drop, internal, dmz.
Q What does a rich rule let you do that a simple service/port rule cannot?
+ Match on source address, log, rate-limit, and accept/reject/drop with fine control
- Only open a port
- Only close a port
- Change the default zone
E Rich rules combine source, service/port, action and logging in one rule.
Q What does `firewall-cmd --add-masquerade` enable?
+ Source NAT, so traffic from an internal network is translated to the host's address
- A new zone
- Port 80 only
- DNS forwarding
E Needed when the host routes traffic for a private network to the internet.
Q A firewalld port-forward rule sends traffic arriving on one port to:
+ Another port (and optionally another host) — e.g. 80 -> 8080
- The default gateway
- The DNS server
- Nowhere
E Use `--add-forward-port=port=80:proto=tcp:toport=8080`.
Q Which command permanently rejects SSH only from 192.168.50.0/24?
+ firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.50.0/24" service name="ssh" reject'
- firewall-cmd --remove-service=ssh
- firewall-cmd --add-port=22/tcp
- firewall-cmd --block ssh
E `man firewalld.richlanguage` has copyable examples for the exam.
Q What is the difference between "reject" and "drop" in a rule?
+ reject replies that the connection is refused; drop silently discards it
- They are identical
- drop replies; reject is silent
- reject is faster
E drop makes the host appear offline to that source.
C Add a rich rule that logs and drops all traffic from 10.0.0.66.
A firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.0.0.66" log prefix="DROP66 " level="info" drop'
E Reload after; check /var/log/messages or the journal for the log prefix.
C Enable masquerading (source NAT) in the current zone permanently.
A firewall-cmd --permanent --add-masquerade
E Then `firewall-cmd --reload`.
C Forward incoming TCP port 80 to port 8080 on this host.
A firewall-cmd --permanent --add-forward-port=port=80:proto=tcp:toport=8080
E Requires masquerade for forwarding to another host.
C Put the source 192.168.10.0/24 into the trusted zone permanently.
A firewall-cmd --permanent --zone=trusted --add-source=192.168.10.0/24
E `--get-active-zones` shows which sources/interfaces map to which zone.
T Zone-based access control (exam-plus)
S Put your management subnet in the "internal" zone with ssh allowed, keep "public" for everything else with only http, and verify.
X firewall-cmd --permanent --zone=internal --add-source=192.168.10.0/24 --add-service=ssh
X firewall-cmd --permanent --zone=public --add-service=http
X firewall-cmd --reload
X firewall-cmd --get-active-zones
V firewall-cmd --zone=internal --list-all and --zone=public --list-all match the intent
T Rich rule with logging
S Reject SSH from one subnet with a logged rich rule, test from that subnet, and read the log.
X firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.50.0/24" service name="ssh" log prefix="SSH-REJ " level="info" reject'
X firewall-cmd --reload
X # from a host in 192.168.50.0/24:  ssh <this-host>   -> refused
X journalctl | grep 'SSH-REJ' | tail
V the connection is rejected and logged
T Port forwarding
S Make the host accept web traffic on port 80 but serve it from a service on 8080, using firewalld.
X firewall-cmd --permanent --add-masquerade
X firewall-cmd --permanent --add-forward-port=port=80:proto=tcp:toport=8080
X firewall-cmd --reload
X # run something listening on 8080, then:
X curl -s http://localhost:80 | head
V traffic to :80 is served by the :8080 service
T Save runtime rules and audit
S Add a couple of runtime-only rules, make them permanent, and produce a full audit of every zone.
X firewall-cmd --add-service=https        # runtime only
X firewall-cmd --runtime-to-permanent
X firewall-cmd --list-all-zones | less
V the https rule persists and you have a full zone audit

- Bridge
- Socket
E A table holds chains; chains hold rules.
Q A base chain must declare its:
+ Type, hook (input/forward/output), and priority
- IP address
- DNS server
- MTU

Q Which command shows the entire active nftables ruleset?

- nft dump
- nftables --list

- Add it to /etc/fstab
- Put it in crontab
- Nothing; it is automatic
E `systemctl enable --now nftables` loads /etc/sysconfig/nftables.conf includes.

+ firewalld manages its own nftables rules; hand rules can conflict or be overwritten
- nftables is slower
- It is illegal
- They never conflict
E Pick one manager per host; for the RHCSA, firewalld is the expected tool.

A nft add table inet filter
E inet covers both IPv4 and IPv6.

#D 68|RH134|Networking: troubleshooting and diagnostics|Diagnose connectivity, ports, DNS and performance methodically.
Q What is a sound order for troubleshooting "I can't reach a server"?
+ Link -> IP/route -> gateway -> DNS -> the remote port/service
- DNS first, always
- Reboot first
- Reinstall the NIC driver
E Work up the stack: is the link up, do I have an IP and route, can I reach the gateway, does the name resolve, is the port open?
Q Which command shows listening TCP/UDP ports with the owning process?
+ ss -tulpn
- netstat -r
- ip route
- dig
E t=TCP, u=UDP, l=listening, p=process, n=numeric.
Q `ping` succeeds to an IP but a website fails by name. The likely problem is:
+ DNS resolution
- The cable
- The default route
- The firewall on your host
E Test with `dig <name>` or `getent hosts <name>`.
Q Which tool combines traceroute and ping to show per-hop loss over time?
+ mtr
- ss
- ethtool
- nmcli
E mtr is excellent for spotting a flaky hop.
Q `ethtool eth0` is used to check:
+ Link speed, duplex and whether the link is detected on a NIC
- DNS servers
- Firewall rules
- Routes
E A half-duplex or down link explains many "slow/no network" issues.
Q Where do you look for NetworkManager errors during troubleshooting?
+ journalctl -u NetworkManager
- /var/log/dns
- /etc/hosts
- dmesg only
E Add `-b` for this boot, `-f` to follow live while you reactivate a connection.
Q `getent hosts server1` is useful because it:
+ Resolves a name using the system's full nsswitch order (files + DNS), like real apps do
- Only queries DNS
- Only reads /etc/hosts
- Pings the host
E It reflects what applications actually see, unlike a raw DNS query.
C Show all interfaces, their state and IPs in one short line each.
A ip -br a
A ip -br addr
E `ip -br link` shows just link state; great for a quick health check.
C Show the routing table including the default gateway.
A ip route
A ip route show
E The default route line (`default via ...`) is the gateway.
C Test whether TCP port 443 is open on a remote host without extra tools.
A nc -zv 192.168.1.50 443
A timeout 3 bash -c 'echo > /dev/tcp/192.168.1.50/443 && echo open'
E `nc -z` scans without sending data; authorized targets only.
C Follow NetworkManager's log live while you reactivate a connection.
A journalctl -u NetworkManager -f
E In another terminal run `nmcli con up <name>` and watch the messages.
T Methodical connectivity triage (exam-plus)
S A host cannot reach an internal server by name. Work the stack: check link, IP/route, gateway, DNS, then the remote port, and identify the failing layer.
X ip -br a; ip -br link            # link + IP
X ip route                          # default route present?
X ping -c2 $(ip route | awk '/default/{print $3}')   # gateway reachable?
X getent hosts server1              # does the name resolve?
X nc -zv server1 22                 # is the service port open?
V you can state which layer is broken and the fix
T DNS troubleshooting
S Diagnose a name that will not resolve: check the resolver, query directly, and confirm the search domain.
X cat /etc/resolv.conf
X dig server1.example.com +short
X getent hosts server1.example.com
X nmcli dev show | grep -i dns

S Find what is listening locally, then verify a remote host's port is reachable from here.
X ss -tulpn
X ss -tulpn | grep :443
X nc -zv 192.168.1.50 443
V you know which local ports listen and whether the remote port is open
T Capture and read traffic for a stubborn issue
S On an authorized host, capture a few packets of a failing connection to see where it stops.
X sudo tcpdump -i eth0 -n host 192.168.1.50 and port 443 -c 20
X # look for SYN with no SYN-ACK (blocked/no service) vs RST (refused)
V you can interpret the handshake to locate the failure
T Link-layer check
S Confirm a NIC's link, speed and duplex, and review recent driver/link messages.
X ethtool eth0 | grep -Ei 'speed|duplex|link detected'
X journalctl -k | grep -i eth0 | tail
V you can confirm the physical link is healthy or spot a flapping NIC
