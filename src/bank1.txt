#D 1|RH124|Shell basics and getting help|Access shell prompts, issue commands with correct syntax, and find answers in man, info and /usr/share/doc.
Q In the prompt `[student@servera ~]$`, what does the final `$` tell you?
+ You are logged in as a regular (non-root) user
- You are logged in as root
- A command is still running in the background
- SELinux is in enforcing mode
E A `$` prompt means a normal user; `#` means root. Always glance at it before running admin commands.
Q Which command searches the short descriptions of all man pages for a keyword?
+ man -k keyword
- man -f keyword
- info -s keyword
- help keyword
E `man -k` is the same as `apropos`. If it returns "nothing appropriate", build the index as root with `mandb`.
Q Which man section documents configuration file formats such as /etc/fstab?
+ Section 5
- Section 1
- Section 8
- Section 3
E Section 1 = user commands, 5 = file formats, 8 = admin commands. Use `man 5 fstab`.
C Open the manual page for the /etc/passwd file format (not the passwd command).
A man 5 passwd
E Without the section number, `man passwd` opens section 1, the command.
Q Where do packages usually install extra documentation such as example config files?
+ /usr/share/doc
- /etc/doc
- /var/doc
- /opt/doc
E Look in `/usr/share/doc/<package>` for READMEs and examples. It is available during the exam.
Q Which keyboard shortcut searches backwards through your bash command history?
+ Ctrl+R
- Ctrl+H
- Ctrl+B
- Ctrl+L
E Press Ctrl+R, type part of an old command, press Ctrl+R again to go further back, Enter to run it.
C Show only the last 20 commands from your history.
A history 20
E `history` alone shows everything; `!N` reruns entry number N.
Q What does `!!` do in bash?
+ Runs the previous command again
- Repeats the last argument of the previous command
- Inverts the exit code of the last command
- Opens the history file in an editor
E `!!` is the whole last command (handy as `sudo !!`). `!$` is only the last argument.
C Find out whether `cd` is a shell builtin, an alias, or a program on disk.
A type cd
E `type` reports how bash resolves a name. Builtins have no separate man page; use `help cd`.
Q Inside a man page, how do you search forward for the word "UID"?
+ Type /UID and press Enter, then n for the next match
- Press Ctrl+F and type UID
- Type :find UID
- Press s and type UID
E man uses the `less` pager: `/pattern` searches forward, `n` next match, `N` previous, `q` quit.
T Find answers only with the built-in documentation
S Without using the internet, find out: (1) which man section documents /etc/shadow, (2) which useradd option sets a specific UID, and (3) which commands have "partition" in their description.
H `man -f name` lists every section that has a page with that name.
H If `man -k` finds nothing, the index has not been built yet.
X man -f shadow
X man 5 shadow
X man useradd        # then type /UID and press n
X man -k partition
X sudo mandb         # only if man -k printed "nothing appropriate"
V man -k partition | head

X !3
X ls -ld /etc/ssh

#D 2|RH124|Managing files and directories|Create, delete, copy and move files and directories; understand the filesystem hierarchy.
Q Where are system-wide configuration files kept on RHEL?
+ /etc
- /usr
- /var
- /opt
E `/etc` holds configuration. `/usr` holds installed software, `/var` holds variable data such as logs.
Q Which directory holds data that changes while the system runs, such as logs, spools and caches?
+ /var
- /etc
- /boot
- /srv
E Logs live in `/var/log`, for example `/var/log/messages` and `/var/log/secure`.
Q Which of these paths is absolute?
+ /home/student/docs
- ../student/docs
- ./docs
- docs/report.txt
E An absolute path starts with `/` and works from any current directory.
C Create the directory tree a/b/c in one command, creating missing parents.
A mkdir -p a/b/c
E Without `-p`, mkdir fails if `a` or `a/b` doesn't exist.
C Copy the directory /etc/skel and everything inside it to /tmp/skelcopy.
A cp -r /etc/skel /tmp/skelcopy
A cp -R /etc/skel /tmp/skelcopy
A cp -a /etc/skel /tmp/skelcopy
E Directories need `-r`. `-a` (archive) also keeps permissions, ownership and timestamps.
Q What is the difference between `rmdir dir` and `rm -r dir`?
+ rmdir only removes empty directories; rm -r removes the directory and its contents
- rmdir asks for confirmation; rm -r never deletes hidden files
- They are identical
- rm -r only works as root
E Use `rmdir` when you want a safety check that a directory is empty.
Q Which files does the glob `file?.txt` match?
+ file1.txt and fileA.txt, but not file10.txt
- file1.txt and file10.txt
- Every file starting with "file"
- Only a file literally named file?.txt
E `?` matches exactly one character, `*` matches any number, `[abc]` matches one of a set.
C Create report1.txt through report5.txt with a single touch command.
A touch report{1..5}.txt
E Brace expansion `{1..5}` expands to 1 2 3 4 5 before the command runs.
Q As a regular user with no aliases, what happens with `mv a.txt b.txt` when b.txt already exists?
+ b.txt is overwritten without any prompt
- mv refuses and prints an error
- mv renames a.txt to b.txt.1
- mv asks for confirmation
E Use `mv -i` to be asked first. On RHEL, root has aliases `rm -i`, `cp -i` and `mv -i` set in /root/.bashrc.
C Go back to the directory you were in just before the current one.
A cd -
E `cd -` toggles between your last two directories. `cd` alone goes home.

#D 3|RH124|Links and finding files|Create hard and soft links, and locate files with find.
Q What is true about a hard link?
+ It points to the same inode as the original file
- It stores the path of the original file
- It breaks when the original file is deleted
- It can point to a directory
E Hard links are extra names for the same inode. The data stays until the last name is removed.
Q What happens to a symbolic link when its target file is deleted?
+ The link remains but is broken (dangling)
- The link is deleted automatically
- The link keeps a copy of the data
- The link now points to /dev/null
E A soft link stores a path. If nothing exists at that path, the link is broken. `ls -l` shows it in red.
Q Which of these can a hard link NOT do?
+ Point to a directory or to a file on another filesystem
- Point to a file in the same directory
- Share the same inode as the original
- Survive deleting the original name
E Soft links can cross filesystems and point to directories; hard links cannot.
C Create a symbolic link /root/hosts-link that points to /etc/hosts.
A ln -s /etc/hosts /root/hosts-link
E Order: `ln -s TARGET LINKNAME`. Leave out `-s` to make a hard link.
C Find every file on the system owned by user natasha, hiding "Permission denied" errors.
A find / -user natasha 2>/dev/null
A find / -user natasha -type f 2>/dev/null
E `2>/dev/null` discards error messages from directories you cannot read.
Q Which find test matches files larger than 100 MiB?
+ -size +100M
- -size 100M+
- -bigger 100M
- -size >100M
E `+` means more than, `-` means less than. Units: k, M, G.
C Find files under /etc that were modified in the last 2 days.
A find /etc -mtime -2
A find /etc -type f -mtime -2
E `-mtime -2` = less than 2 days ago. Use `-mmin` for minutes.
Q In `find / -user harry -exec cp -a {} /root/harry/ \;` what does `{}` stand for?
+ Each path that find matched
- The current directory
- The user's home directory
- The previous command's output
E `\;` ends the -exec command. find runs it once for every match, putting the path in place of `{}`.
Q What does the second column of `ls -l` output show for a file?
+ The number of hard links to it
- The inode number
- The file size in blocks
- The number of users who opened it
E `ls -i` shows the inode number. A link count of 2 on a file means one extra hard link exists.
C Find every file under /usr that has the SUID bit set.
A find /usr -perm -4000
A find /usr -perm -u+s
A find /usr -type f -perm -4000
A find /usr -perm /4000
E `-perm -4000` means "at least these bits". `ls -l` shows SUID as an `s` in the owner execute slot.
T Hard links vs soft links
S In ~/linklab create original.txt containing "version 1". Make a hard link hard.txt and a soft link soft.txt. Compare inode numbers, delete original.txt, and see which link still shows the content.
X mkdir ~/linklab && cd ~/linklab
X echo "version 1" > original.txt
X ln original.txt hard.txt
X ln -s original.txt soft.txt
X ls -li
X rm original.txt
X cat hard.txt       # still works
X cat soft.txt       # No such file or directory
V ls -li ~/linklab
T Find a user's files and copy them (exam classic)
S Create user harry and give him a few files in /tmp and his home. Then, as root, find every regular file owned by harry and copy it into /root/harryfiles, keeping permissions.
H Create the destination directory before running find.
X useradd harry
X sudo -u harry touch /tmp/harry1 /home/harry/notes
X mkdir -p /root/harryfiles
X find / -user harry -type f -exec cp -a {} /root/harryfiles/ \; 2>/dev/null
V ls -l /root/harryfiles

#D 4|RH124|Redirection and pipes|Use input-output redirection (>, >>, |, 2>, etc.).
Q What does `2>` redirect?
+ Standard error
- Standard output
- Standard input
- Both output streams
E File descriptors: 0 = stdin, 1 = stdout, 2 = stderr.
Q What does `command > out.txt 2>&1` do?
+ Sends both standard output and standard error to out.txt
- Sends only errors to out.txt
- Appends to out.txt
- Sends output to out.txt and errors to a file called 1
E `2>&1` means "send stderr to wherever stdout goes now". The order matters.
Q With `command 2>&1 > file`, where do the errors go?
+ To the terminal
- To file
- To /dev/null
- Nowhere; bash reports a syntax error
E Redirections are processed left to right. At the time of `2>&1`, stdout still pointed at the terminal.
C Append the line "hello" to notes.txt without overwriting it.
A echo hello >> notes.txt
A echo "hello" >> notes.txt
A echo 'hello' >> notes.txt
E `>` truncates the file first. `>>` appends.
C Search the whole filesystem for files named passwd, throwing away all error messages.
A find / -name passwd 2>/dev/null
E /dev/null discards everything written to it.
Q What does `tee` do?
+ Copies its input to a file and to standard output at the same time
- Splits a file into two parts
- Joins two files side by side
- Redirects errors to a file
E Example: `ls -l | tee list.txt | wc -l` saves the listing and still counts it.
C Save the output of `ls -l /etc` to /root/etc.txt and also show it on the screen.
A ls -l /etc | tee /root/etc.txt
E Use `tee -a` to append instead of overwrite.
Q In bash, what does `&> file` do?
+ Redirects both stdout and stderr to file
- Runs the command in the background and writes to file
- Redirects only stderr to file
- Appends stdout to file
E `&> file` is short for `> file 2>&1`. Use `&>> file` to append both.
Q What does the pipe `|` connect?
+ The stdout of the left command to the stdin of the right command
- The stderr of the left command to the right command
- Two files into one
- The exit code of the left command to the right command
E Errors are not piped unless you add `2>&1` first (or use `|&`).
C Count the number of lines in /etc/passwd.
A wc -l /etc/passwd
A wc -l < /etc/passwd
A cat /etc/passwd | wc -l
E Each line in /etc/passwd is one account, so this also counts accounts.
T Redirection practice
S Run `ls /etc /nonexistent` four ways: output only to ok.txt, errors only to err.txt, both to all.txt, and append a second run to all.txt. Check each file after every step.
X cd ~ && ls /etc /nonexistent > ok.txt
X ls /etc /nonexistent 2> err.txt
X ls /etc /nonexistent &> all.txt
X ls /etc /nonexistent >> all.txt 2>&1
V wc -l ok.txt err.txt all.txt
T Build a pipeline
S Show the 5 largest files in /usr/bin with their sizes in human-readable form and save that list to /root/biggest.txt while also printing it.
H `ls -lS` sorts by size, largest first.
X ls -lhS /usr/bin | head -n 6 | tee /root/biggest.txt
X # head -n 6 because the first line of ls -l is the "total" line
V cat /root/biggest.txt

Q Which regular expression matches lines that end with "bash"?
+ bash$

- bash^
- $bash
E `$` anchors to the end of the line. `^$` matches an empty line.
Q In a basic regular expression, what does `.` match?
+ Any single character
- A literal dot only
- Zero or more characters
- The end of the line
E Escape it as `\.` to match a real dot, for example `grep '\.conf$'`.
C Show all lines in /etc/ssh/sshd_config that are neither comments nor empty lines.

A grep -vE '^#|^$' /etc/ssh/sshd_config

Q What does `grep -E 'cat|dog' file` print?
+ Lines containing cat or dog
- Lines containing cat followed by dog
- Only the words cat and dog
- Lines that contain neither word
E `-E` turns on extended regex so `|`, `+`, `?` and `{n}` work without backslashes.

- It matches case-insensitively
- It prints the word count
- It searches recursively

#D 8|RH124|Passwords, aging and sudo|Change passwords and adjust password aging; configure privileged access.
Q What does `chage -M 90 harry` set?
+ harry must change his password at most every 90 days
- harry must wait 90 days before changing his password
- harry's account expires in 90 days
- harry gets a warning 90 days before expiry
E -M max days, -m min days, -W warning days, -I inactive days, -E account expiry date.
C Force harry to change his password at his next login.
A chage -d 0 harry
A passwd -e harry
A passwd --expire harry
E Setting the last-change date to 0 means the password counts as already expired.
C Make natasha's account expire on 2026-12-31.
A chage -E 2026-12-31 natasha
A usermod -e 2026-12-31 natasha
E The account (not just the password) stops working after this date.
Q Which file sets the default password-aging values for users created in the future?
+ /etc/login.defs
- /etc/default/useradd
- /etc/shadow
- /etc/security/pwquality.conf
E Look for PASS_MAX_DAYS, PASS_MIN_DAYS and PASS_WARN_AGE.
Q You edit PASS_MAX_DAYS in /etc/login.defs. Which accounts does it affect?
+ Only accounts created after the change
- All existing accounts immediately
- Only the root account
- All accounts after a reboot
E For existing users, run `chage` on each one.
C Show the password-aging information for harry.

#D 10|RH124|Special permissions, umask and ACLs|Manage default file permissions and diagnose and correct file permission problems.
Q What does the SGID bit do on a directory?
+ New files created in it get the directory's group
- Only the group owner may delete files in it
- Files inside it run with group privileges
- Group members get write access automatically
E This is how you build shared team directories.
Q What does the sticky bit do on a directory such as /tmp?
+ Users can only delete their own files, even with write permission on the directory
- Files are never deleted at reboot
- New files inherit the directory's owner
- Only root can create files
E /tmp shows `drwxrwxrwt`. In octal the sticky bit is 1, e.g. `chmod 1777`.
C Set the SGID bit on /home/managers using symbolic mode.
A chmod g+s /home/managers
E Octal version: `chmod 2770 /home/managers` (2 = SGID, 4 = SUID, 1 = sticky).
Q With umask 027, what permissions does a newly created regular file get?
+ 640 (rw-r-----)
- 750 (rwxr-x---)
- 027 (----w-rwx)
- 600 (rw-------)
E Files start from 666, directories from 777, then the umask bits are removed: 666-027 = 640, 777-027 = 750.
C Set the umask of your current shell so new files are 600 and new directories 700.
A umask 077
A umask 0077
E Run `umask` with no argument to see the current value.
Q How do you make a user's umask survive logout and reboot?
+ Put the umask command in that user's ~/.bashrc or ~/.bash_profile
- Run umask as root
- Add it to /etc/fstab
- Set it with chmod on the home directory
E For every user, use a script in /etc/profile.d/ instead.
C Give user natasha read and write access to /var/tmp/fstab using an ACL.
A setfacl -m u:natasha:rw /var/tmp/fstab
A setfacl -m u:natasha:rw- /var/tmp/fstab
A setfacl -m user:natasha:rw /var/tmp/fstab
E View the result with `getfacl /var/tmp/fstab`.
C Use an ACL so that user harry has no access at all to /var/tmp/fstab.

A setfacl -m u:harry:- /var/tmp/fstab
A setfacl -m u:harry:0 /var/tmp/fstab
A setfacl -m user:harry:--- /var/tmp/fstab
E A named-user ACL entry takes priority over the "other" permissions.
Q `ls -l /usr/bin/passwd` shows `-rwsr-xr-x`. What does the `s` mean?

- The file is a socket
- The file is sticky
- The file is signed
E This is how normal users can update /etc/shadow through passwd. A capital `S` means SUID is set but execute is not.

- The user needs to be in the wheel group
- The file needs the sticky bit
