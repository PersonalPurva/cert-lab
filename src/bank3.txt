#D 22|RH134|Shell scripts: basics|Process script inputs ($1, $2, etc.) and process the output of shell commands within scripts.
Q What should the first line of a bash script be?
+ #!/bin/bash
- #bash
- !#/bin/bash
- //bin/bash
E This "shebang" line tells the kernel which interpreter runs the file.
C Make script.sh executable for everyone.
A chmod +x script.sh
A chmod a+x script.sh
A chmod 755 script.sh
E Run it as `./script.sh`, or put it in /usr/local/bin so it's on the PATH.
Q Inside a script, what are $1, $# and $@?
+ The first argument, the number of arguments, and all arguments
- The script name, the PID, and the exit code
- The first line, the line count, and all lines
- The user, the group, and the home directory
E $0 is the script's own name. Quote "$@" so arguments with spaces stay intact.
Q What does $? contain?
+ The exit status of the last command (0 means success)
- The PID of the last background job
- The number of arguments
- The current user's UID
E Check it right after the command, because every command overwrites it.
C Store the output of the `hostname` command in a variable named host.
A host=$(hostname)
A host=`hostname`
E Prefer $( ); it nests cleanly and is easier to read.
Q What happens with `count = 5` in bash?
+ An error: bash tries to run a command named count
- count is set to 5
- count is set to " 5"
- It compares count with 5
E Assignments must have no spaces around the =.
Q What is the difference between "$HOME" and '$HOME'?
+ Double quotes expand the variable; single quotes keep the text literally
- Single quotes expand it; double quotes do not
- Both expand it
- Neither expands it
E Use double quotes around variables to keep spaces intact and still expand them.
C Print the number of arguments that were passed to the script.
A echo $#
A echo "$#"
E Useful for checking that the user passed what the script needs.
Q What does `exit 1` do in a script?
+ Ends the script immediately with exit status 1 (failure)
- Skips the next line
- Restarts the script
- Logs out the user
E By convention, 0 means success and anything else means an error.

#D 23|RH134|Shell scripts: conditions and loops|Conditionally execute code and use looping constructs to process files and command-line input.
Q Which test is true when `file` exists and is a regular file?
+ [ -f file ]
- [ -e -r file ]
- [ -d file ]
- [ file ]
E -e exists (any type), -f regular file, -d directory, -r readable, -x executable, -s not empty.
Q Which is the correct numeric comparison "a is greater than 5"?
+ [ "$a" -gt 5 ]
- [ "$a" > 5 ]
- [ $a gt 5 ]
- [ "$a" => 5 ]
E Numbers: -eq -ne -lt -le -gt -ge. Strings: = and !=. Inside [ ], `>` means redirection.
C Write a one-line for loop that prints the numbers 1 to 5.
A for i in {1..5}; do echo $i; done
A for i in $(seq 1 5); do echo $i; done
A for i in 1 2 3 4 5; do echo $i; done
A for i in {1..5}; do echo "$i"; done
E Loops can also go over files (`for f in /etc/*.conf`) or command output.
Q What does `while read line; do echo "$line"; done < users.txt` do?
+ Reads users.txt one line at a time into $line
- Reads the whole file into one variable
- Waits for the user to type a line
- Only reads the first line
E This is the safe way to process a list of names from a file.
Q When is `[ -z "$1" ]` true?
+ When $1 is empty or not given
- When $1 is zero
- When $1 is a file with size zero
- When $1 is a directory
E `-n` is the opposite: true when the string is not empty.
Q In `cmd1 && cmd2 || cmd3`, when does cmd3 run?
+ When cmd1 fails, or when cmd1 succeeds and cmd2 fails
- Only when cmd1 succeeds
- Always
- Never
E && runs the next command on success, || on failure. For clear logic, use if/then/else.
C Using the test brackets, print "yes" only if /etc/hosts is readable.
A [ -r /etc/hosts ] && echo yes
A test -r /etc/hosts && echo yes
A [[ -r /etc/hosts ]] && echo yes
E `test` and `[ ]` are the same builtin.
Q Which if statement has correct syntax?
+ if [ "$x" = "yes" ]; then echo ok; fi
- if [$x = yes] then echo ok fi
- if ( $x == yes ) { echo ok }
- if [ "$x" = "yes" ] echo ok; end
E Spaces inside the brackets are required. Close with `fi`.
Q Which word ends a case block?
+ esac
- end
- done
- fi
E case is spelled backwards; each branch ends with `;;`.

Q What is the order of the five time fields in a crontab line?
+ minute, hour, day of month, month, day of week
- hour, minute, day of month, month, day of week
- minute, hour, month, day of month, day of week
- second, minute, hour, day, month
E Tip: `cat /etc/crontab` shows a reminder diagram of the fields.
Q What does `*/10 * * * *` mean?
+ Every 10 minutes
- At 10 minutes past every hour
- Every 10 hours
- On the 10th of every month
E `10 * * * *` would be minute 10 of every hour.
Q What does `30 14 * * 1-5` mean?
+ At 14:30, Monday to Friday
- At 14:30 on days 1 to 5 of the month
- Every 30 minutes from 14:00 to 17:00
- At 30 minutes past 2 AM, Monday to Friday
E Day of week: 0 or 7 = Sunday, 1 = Monday ... 6 = Saturday.

A crontab -u natasha -l
E `crontab -r` deletes the whole crontab. Be careful.
Q How are lines in /etc/crontab and /etc/cron.d/* different from a user crontab?

- They use seconds instead of minutes
- They cannot use */N
- They only run at boot
E Example: `30 2 * * 0  root  /usr/local/bin/backup.sh`.

- The job keeps running forever
- The timer survives `systemctl daemon-reload`
