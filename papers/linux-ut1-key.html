Q.3 — Short notes (3 marks each)
a) su user1 vs su - user1: su user1 switches to user1 but keeps your current environment (same PATH, same directory). su - user1 starts a login shell: it loads user1's full environment and moves to their home directory. Both ask for user1's (the target user's) password — only sudo asks for your own.
b) /etc/passwd fields — seven colon-separated fields: 
name : x : UID : GID : comment : home : shell
root : x :  0  :  0  :  root   : /root : /bin/bash
username, password placeholder (x — real hash is in /etc/shadow), User ID, primary Group ID, comment/full-name, home directory, and login shell.
c) SGID bit on a directory: with SGID set, any new file created inside inherits the directory's group (instead of the creator's primary group). This is ideal for a shared team folder so every member's new files automatically belong to the common group. Set it with: 
chmod g+s /data/impdata
# or in octal:  chmod 2771 /data/impdata
It shows as an s in the group slot: drwxrws---.
Q.4 — Practical task (9 marks)
A) (4) 
groupadd redhat
useradd -G redhat amit
useradd -G redhat un1
passwd amit
B) (5) 
mkdir -p /data/impdata
chown amit /data/impdata
chgrp redhat /data/impdata
chmod 771 /data/impdata
chmod g+s /data/impdata
ls -ld /data/impdata
# verify:  drwxrws--x. amit redhat ... /data/impdata

B) (5) 
usermod -aG wheel deep
su - deep
sudo cat /etc/shadow               # runs as root with deep's own password
Why visudo: it checks the syntax before saving, so a mistake can't leave a broken /etc/sudoers that locks everyone out of sudo.
